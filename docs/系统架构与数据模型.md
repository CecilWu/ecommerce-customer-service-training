# 系统架构与数据模型

本文描述当前代码的真实结构。发生冲突时，以 `prisma/schema.prisma`、API 路由和运行结果为准。

## 1. 技术架构

| 层次 | 实现 |
|---|---|
| 页面与服务端渲染 | Next.js 15 App Router、React 19 |
| 语言 | TypeScript 5.9 |
| 数据访问 | Prisma 6.19 |
| 数据库 | SQLite |
| 登录 | HMAC 签名 Cookie + 数据库账号状态复核 |
| 密码 | Node.js `scrypt` 哈希 |
| AI | OpenAI 兼容 `/chat/completions` |
| PDF | 浏览器端 `html2canvas` + `jsPDF` |
| 部署 | Node.js 或 Docker Compose |

浏览器只负责交互和展示。账号、权限、训练、评分、报告和证书数据均由 Next.js 服务端访问 Prisma。

## 2. 目录职责

| 目录 | 职责 |
|---|---|
| `app/` | 页面、布局、Route Handler API |
| `components/` | 跨页面复用组件 |
| `lib/` | 认证、权限、AI、评分、检索和业务函数 |
| `prisma/` | 唯一数据模型、开发数据库和种子数据 |
| `public/` | 静态图片与师父签章 |
| `css/` | 全局样式 |
| `scripts/` | 预检、完整性、冒烟、密钥轮换和部署打包 |
| `docker/` | 容器启动脚本 |
| `docs/` | 现行说明文档 |

根目录不保存历史版本、数据库备份和构建缓存。运行时缓存由 Next.js 重新生成，数据库备份应放在项目目录之外。

## 3. 认证与权限

登录成功后生成包含用户 ID、角色和过期时间的签名 Cookie `ecs_session`，默认有效期 7 天。每次读取会话仍会查询数据库，账号停用后旧 Cookie 不能继续使用。

页面布局负责角色入口保护，API 仍必须独立校验：

- `ADMIN`：平台级数据；
- `MASTER`：通过 `ownerId`、`createdById` 和任务归属限制业务范围；
- `APPRENTICE`：通过 `userId`、组织和报名关系限制个人数据。

超级管理员不是独立角色，而是 `ADMIN` 且用户名为 `admin`。

## 4. 核心数据实体

### User

账号实体。包含规范化用户名、密码哈希、角色、姓名、班级快照、组织、签章路径和启用状态。

主要关系：

- 师父拥有多个 `OrganizationUnit`；
- 师父或管理员创建产品与任务；
- 徒弟拥有报名、会话和证书；
- 师父可作为报告复核人。

### OrganizationUnit

班级或部门，名称全局唯一，类型为 `CLASS` 或 `DEPARTMENT`。必须有一位 `MASTER` 所有者，可关联成员和任务。

### Product 与 FaqDocument

`Product` 保存产品名称、类目、说明、规则、标准话术和禁用话术。`createdById` 为空的是系统共享产品。

`FaqDocument` 保存知识标题、来源和正文，可关联具体产品，也可作为通用知识。当前检索最多读取最近 30 份文档并在内存中排序。

### Task

任务保存：

- 类型、产品和组织；
- 场景、客户画像、订单信息；
- 难度、训练目标；
- 时间和轮次上限；
- 重试、补考、提示和报告可见设置；
- 归档状态及创建人。

任务与产品是限制删除关系；删除已被任务使用的产品会失败。组织删除后任务组织可置空。

### TaskEnrollment

徒弟与任务的报名中间表，`taskId + userId` 唯一。组织或账号变化时，系统会重建该徒弟对有效组织任务的报名。

### TrainingSession 与 ChatMessage

会话状态：

- `RUNNING`：进行中；
- `SUBMITTED`：已生成报告；
- `REVIEWED`：师父已复核。

会话保存客户状态 JSON、开始和提交时间。消息按 `CUSTOMER`、`APPRENTICE`、`SYSTEM` 保存，并保留情绪、意图和创建时间。

### ScoreReport

每个会话最多一份报告，保存总分、原始分、等级、通过状态、摘要、完整报告 JSON、复核人和复核时间。

详细维度、风险、优点、问题和建议话术均在 `reportJson` 中。修改报告结构时必须兼容历史 JSON。

### Certificate

保存证书编号、用户、签发时间和更新时间。当前数据库没有强制 `userId` 唯一，业务代码按每人一证处理。

### AiProvider

保存服务商名称、类型、Base URL、模型、加密 API Key、启用状态和更新时间。业务上只允许一个启用配置，数据库层没有唯一约束，完整性脚本负责检查。

## 5. 训练数据流

### 开始训练

`POST /api/training/start`

1. 校验登录、角色、任务和报名关系；
2. 检查重试规则；
3. 检索 FAQ；
4. 生成 AI 客户开场；
5. 事务内清理同任务未评分的旧进行中会话；
6. 创建会话和首条客户消息。

### 发送消息

`POST /api/training/message`

1. 校验会话属于当前徒弟且仍为 `RUNNING`；
2. 读取历史消息、任务、产品和知识；
3. 调用 AI 或本地回退生成客户回复；
4. 使用 `updatedAt` 做乐观并发检查；
5. 事务保存徒弟消息、客户消息和新客户状态。

### 提交评分

`POST /api/training/score`

1. 校验会话与最低消息条件；
2. 生成评分报告；
3. 事务认领会话并创建唯一报告；
4. 会话变为 `SUBMITTED`；
5. 正式考核同步证书。

### 师父复核

`POST /api/mentor/reports/[reportId]`

校验任务归属后更新报告总分、等级、通过状态、总结、评语和复核信息。正式考核复核后再次同步证书。

## 6. API 分组

| 前缀 | 用途 |
|---|---|
| `/api/auth/*` | 登录、退出、注册、当前用户 |
| `/api/account/*` | 个人密码 |
| `/api/admin/*` | 账号、组织、AI 服务商 |
| `/api/products`、`/api/faq` | 产品与知识 |
| `/api/tasks/*` | 任务、报名和 AI 辅助 |
| `/api/training/*` | 正式训练主流程 |
| `/api/reports` | 徒弟报告查询 |
| `/api/mentor/*` | 报告复核和签章 |
| `/api/docs/*` | 文档读取与下载 |
| `/api/health` | 运行和数据库健康检查 |

系统已移除不持久化的样例客户、样例评分 API 和样例报告页面，避免与正式训练主流程并存。

## 7. 文件与进程约束

- SQLite 写入文件由 `DATABASE_URL` 指定；
- 签章保存到 `public/images/signatures`；
- 多实例会产生 SQLite 写锁、签章不同步和会话状态竞争；
- 生产环境应固定单实例，并把数据库与签章目录挂载到持久卷；
- `.env`、数据库、签章和部署备份不得提交或打入源码包。

## 8. 数据变更规范

1. 修改 `prisma/schema.prisma`。
2. 在数据库副本验证 `prisma db push` 或正式迁移方案。
3. 更新种子数据和所有受影响查询。
4. 运行类型、构建、完整性与冒烟测试。
5. 生产升级前同时备份数据库、环境变量和签章。

项目不再保存零散的手工迁移 SQL；Prisma Schema 是唯一结构来源。复杂生产迁移应随具体版本提供一次性、可审计的迁移脚本，执行完成后归入版本控制历史。
