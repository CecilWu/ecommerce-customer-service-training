# 阿里云宝塔部署教程：与 666 系统共存，并预留域名和 SSL

本文针对当前这台服务器：

| 项目 | 配置 |
|---|---|
| 公网 IP | `YOUR_SERVER_IP` |
| 已有系统入口 | `http://YOUR_SERVER_IP:666` |
| 电商客服当前入口 | `http://YOUR_SERVER_IP:777` |
| 电商客服容器内部入口 | `http://127.0.0.1:17777` |
| 当前 HTTPS | 暂不使用 |
| 正式域名 | `https://training.example.com` |
| 部署方式 | 已有宝塔 Nginx + Docker Compose |

## 0. 会不会和 666 系统冲突

不会。两个系统使用的端口、容器和数据目录不同：

```text
已有高职考系统
浏览器 :666 → 宝塔 Nginx :666 → 127.0.0.1:18080 → 高职考 Web 容器

新电商客服系统
浏览器 :777 → 同一个宝塔 Nginx :777 → 127.0.0.1:17777 → 电商客服容器
```

一个 Nginx 可以同时监听多个端口。`666`、`777`、`18080`、`17777` 各不相同，因此不会发生端口占用冲突。以后多个域名共用 `80/443` 也没有问题，Nginx 会按域名区分站点。

需要注意的不是端口，而是服务器资源。2 核 4G 同时运行两个系统通常可用于低并发教学，但首次 Docker 构建会临时占用较多内存和 CPU。服务器应保留约 4 GB Swap，并定期查看 `free -h`、`df -h` 和 `docker stats --no-stream`。

### 绝对不要动已有系统

- 不删除或修改现有 `666` 网站；
- 不修改现有反向代理 `127.0.0.1:18080`；
- 不停止、卸载或重复安装 Nginx；
- 不删除 `/srv/gzk` 及其容器、网络、数据库或备份；
- 电商客服只使用 `/www/wwwroot/ecommerce-training` 和容器名 `ecommerce-cs-training`。

## 1. 当前和未来的推荐架构

电商客服从第一次部署起就通过 Nginx 访问。Docker 只绑定本机回环地址：

```env
APP_BIND_ADDRESS="127.0.0.1"
APP_PORT="17777"
```

这意味着外网无法绕过 Nginx 直接访问容器。以后绑定域名时仍代理到 `127.0.0.1:17777`，不需要改代码、换容器端口或重新构建镜像。

当前 HTTP 模式：

```env
APP_URL="http://YOUR_SERVER_IP:777"
NEXT_PUBLIC_APP_URL="http://YOUR_SERVER_IP:777"
SESSION_COOKIE_SECURE="false"
```

当前正式 HTTPS 模式：

```env
APP_URL="https://training.example.com"
NEXT_PUBLIC_APP_URL="https://training.example.com"
SESSION_COOKIE_SECURE="true"
```

`APP_URL` 是服务端运行时标准地址，登录、退出和表单跳转会使用它；因此切换域名不需要重新构建 Docker 镜像，只需修改配置并重建容器实例。

## 2. 当前 HTTP 风险

HTTP 不加密，账号、密码和登录 Cookie 在网络传输中可能被窃听。当前 `IP:777` 只适合临时测试、课堂内网或限制访问来源的环境。

如果 ECS 位于中国内地，正式对外提供网站服务前应完成域名备案。参考：[阿里云通用网站备案要求](https://help.aliyun.com/zh/icp-filing/basic-icp-service/product-overview/icp-filing-requirements-for-a-regular-website)。

## 4. 部署前检查已有服务器

先在宝塔终端逐条执行：

```bash
ss -lntp | grep -E ':(666|777|17777|18080)\b' || true
docker ps --format 'table {{.Names}}\t{{.Ports}}\t{{.Status}}'
free -h
df -h
/www/server/nginx/sbin/nginx -t
```

正确情况：

- `666` 和 `18080` 可以已被高职考系统使用；
- 第一次部署前，`777` 和 `17777` 应没有程序占用；
- Nginx 配置检查显示 `syntax is ok` 和 `test is successful`；
- 不能已有一个无关容器叫 `ecommerce-cs-training`。

如果 `777` 或 `17777` 已被占用，先查明占用程序，不要强行停止：

```bash
ss -lntp | grep -E ':(777|17777)\b'
```

## 5. 阿里云安全组与宝塔防火墙

当前阶段：

| 端口 | 来源 | 用途 |
|---|---|---|
| TCP 22 | 你自己的公网 IP `/32` | SSH |
| TCP 666 | 保持原规则 | 已有高职考系统 |
| TCP 777 | 允许使用者 IP；必须公开时才用 `0.0.0.0/0` | 电商客服 HTTP |
| 宝塔面板实际端口 | 你自己的公网 IP `/32` | 宝塔管理 |

不要对公网开放 `17777`、`18080`、`3000`、`3306` 或 `5432`。`17777` 只允许服务器本机 Nginx 访问，不需要添加安全组规则或防火墙规则。

宝塔 → 安全 → 系统防火墙，只新增 `TCP 777` 放行规则，不要删除原来的 `666` 规则。

阿里云官方建议遵循最小权限原则，管理端口限制为可信 IP；正式 Web 站点主要开放 `80/443`。参考：[阿里云安全组说明](https://help.aliyun.com/zh/ecs/user-guide/start-using-security-groups)。

## 6. 确认 Nginx、Docker 和 Swap

已有高职考系统正在通过宝塔 Nginx 运行，所以不要重新安装或切换 Nginx。只检查服务：

```bash
/www/server/nginx/sbin/nginx -v
/www/server/nginx/sbin/nginx -t
docker --version
docker compose version
```

如果 Docker Compose 不存在，在宝塔左侧“Docker”中按提示安装。不要安装第二套 Nginx、MySQL、PostgreSQL 或 PHP。

检查 Swap：

```bash
free -h
swapon --show
```

如果现有 Swap 已经约 4 GB，无需处理。如果完全没有 Swap，执行一次：

```bash
fallocate -l 4G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
grep -q '^/swapfile ' /etc/fstab || echo '/swapfile swap swap defaults 0 0' >> /etc/fstab
free -h
```

## 8. 填写 docker.env

在宝塔文件管理器编辑：

```text
/www/wwwroot/ecommerce-training/docker.env
```

新资料包应已预填下面六项，不要改成 `0.0.0.0:777`：

```env
APP_URL="http://YOUR_SERVER_IP:777"
NEXT_PUBLIC_APP_URL="http://YOUR_SERVER_IP:777"
SESSION_COOKIE_SECURE="false"
APP_BIND_ADDRESS="127.0.0.1"
APP_PORT="17777"
INIT_DEMO_DATA="false"
```

完整配置类似：

```env
DATABASE_URL="file:/data/prisma/prod.db"
SESSION_SECRET="服务器新生成的随机密钥"
AI_CONFIG_ENCRYPTION_KEY="从本地原环境密钥文件抄写的原值"
APP_URL="http://YOUR_SERVER_IP:777"
NEXT_PUBLIC_APP_URL="http://YOUR_SERVER_IP:777"
SESSION_COOKIE_SECURE="false"

APP_BIND_ADDRESS="127.0.0.1"
APP_PORT="17777"
INIT_DEMO_DATA="false"

AI_MODE="openai"
OPENAI_BASE_URL="https://api.deepseek.com"
OPENAI_API_KEY=""
OPENAI_MODEL="deepseek-chat"
```

生成新会话密钥：

```bash
openssl rand -hex 32
```

把输出填入 `SESSION_SECRET`。

`AI_CONFIG_ENCRYPTION_KEY` 不能重新生成。打开自己电脑中的：

```text
本地保管-绝对不要上传/原环境密钥-只用于人工抄写.env.txt
```

只把原 `AI_CONFIG_ENCRYPTION_KEY` 的值手工抄入服务器。确认没有示例占位值：

```bash
grep -n 'CHANGE_ME' /www/wwwroot/ecommerce-training/docker.env
```

没有输出才正确。

## 9. 构建和启动电商客服容器

在 2 核 4G 服务器上串行执行，不要同时重建高职考系统：

```bash
cd /www/wwwroot/ecommerce-training
COMPOSE_PARALLEL_LIMIT=1 docker compose --env-file docker.env build
docker compose --env-file docker.env up -d
docker compose --env-file docker.env ps
docker compose --env-file docker.env logs --tail=200 ecommerce-cs-training
```

最终容器应显示 `healthy`。检查内部服务：

```bash
curl -fsS http://127.0.0.1:17777/api/health
ss -lntp | grep ':17777'
```

正常健康检查应包含：

```json
{"status":"ok","database":"ready"}
```

`ss` 应显示 `127.0.0.1:17777`，不能显示 `0.0.0.0:17777`。

## 10. 在宝塔创建 777 反向代理

不要修改现有 `666` 网站。在宝塔“网站”中新增一个独立的 HTML/静态站点：

```text
站点域名：YOUR_SERVER_IP:777
数据库：不创建
PHP：纯静态
站点备注：电商客服训练系统
```

打开新站点 → 反向代理 → 添加反向代理：

```text
代理名称：ecommerce-training
目标 URL：http://127.0.0.1:17777
发送域名：YOUR_SERVER_IP:777
内容替换：留空
缓存：关闭
```

宝塔官方操作说明：[反向代理配置指南](https://docs.bt.cn/user-guide/site/php/site-config/reverse-proxy)。

在反向代理配置中确认请求头包含以下内容；缺少时在该代理的配置文件中补充到 `location` 内：

```nginx
proxy_set_header Host $http_host;
proxy_set_header X-Forwarded-Host $http_host;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
```

保存后先检查再重载 Nginx：

```bash
/www/server/nginx/sbin/nginx -t
/www/server/nginx/sbin/nginx -s reload
```

如果配置检查失败，不要重启 Nginx；回到宝塔撤销刚才的错误修改。现有 `666` 系统在 Nginx 配置正确前不要动。

检查 Nginx 入口：

```bash
curl -fsS -H 'Host: YOUR_SERVER_IP:777' http://127.0.0.1:777/api/health
ss -lntp | grep -E ':(666|777|17777|18080)\b'
```

## 12. 切换到正式域名和 SSL

以下操作不需要修改代码，也不需要重新构建镜像。当前正式域名为 `training.example.com`。

### 第一步：准备域名

1. 域名完成实名认证；
2. 中国内地 ECS 正式提供网站前完成 ICP 备案；
3. 添加 DNS `A` 记录：`training.example.com` → `YOUR_SERVER_IP`；
4. 等待解析生效，可用 `ping training.example.com` 或 DNS 查询工具确认。

### 第二步：放行 80 和 443

在阿里云安全组和宝塔系统防火墙放行：

```text
TCP 80
TCP 443
```

先不要关闭 `777`，等新域名完整验收后再关闭。

### 第三步：创建域名站点

在宝塔新建 HTML/静态站点：

```text
域名：training.example.com
数据库：不创建
PHP：纯静态
```

为域名站点添加反向代理：

```text
目标 URL：http://127.0.0.1:17777
发送域名：training.example.com
缓存：关闭
```

仍确认代理请求头包含 `Host`、`X-Forwarded-Host`、`X-Forwarded-Proto`、`X-Real-IP` 和 `X-Forwarded-For`。

### 第四步：申请并开启 SSL

域名站点 → SSL，使用宝塔提供的 Let's Encrypt/ACME 或上传已有证书。证书签发成功后开启“强制 HTTPS”。申请证书时域名必须已经正确解析，端口和验证路径必须可访问。参考：[宝塔 SSL 证书部署文档](https://docs.bt.cn/user-guide/site/php/site-config/ssl)。

### 第五步：切换应用标准地址

编辑 `/www/wwwroot/ecommerce-training/docker.env`，只修改三行：

```env
APP_URL="https://training.example.com"
NEXT_PUBLIC_APP_URL="https://training.example.com"
SESSION_COOKIE_SECURE="true"
```

下面两行永久保持不变：

```env
APP_BIND_ADDRESS="127.0.0.1"
APP_PORT="17777"
```

应用新配置，不需要重新 build：

```bash
cd /www/wwwroot/ecommerce-training
docker compose --env-file docker.env up -d --force-recreate
docker compose --env-file docker.env ps
```

然后用浏览器无痕窗口访问：

```text
https://training.example.com
```

检查证书、登录、退出、表单提交、图片和健康检查。由于域名改变，需要重新登录一次属于正常现象。

### 第六步：关闭临时 777 入口

域名 HTTPS 完整验收后：

1. 删除阿里云安全组中的公网 `777` 放行规则；
2. 删除宝塔系统防火墙中的 `777` 放行规则；
3. 停用或删除宝塔的 `YOUR_SERVER_IP:777` 临时站点；
4. 不要删除域名站点，也不要关闭 `127.0.0.1:17777` 容器；
5. 保持原高职考系统 `666` 不变。

最终公网只需按业务需要开放 `80/443`，内部 `17777/18080` 始终不对公网开放。

## 13. 使用一键更新包

日常版本升级不要再次上传首次部署包中的数据库。使用项目根目录的 `制作阿里云一键更新包.command` 生成更新包，更新包只包含源码和更新脚本。

在本地双击：

```text
制作阿里云一键更新包.command
```

生成文件位于项目的 `发布包` 文件夹。只把其中最新的：

```text
电商客服系统-一键更新-日期时间.tar.gz
```

上传到服务器 `/www/wwwroot`。然后在宝塔终端执行，文件名按实际上传名称填写：

```bash
cd /www/wwwroot
tar -xzf 电商客服系统-一键更新-日期时间.tar.gz
sh 电商客服系统-一键更新-日期时间/一键更新.sh
```

更新脚本会自动完成：

1. 校验更新包完整性和服务器磁盘空间；
2. 备份现有源码、`docker.env`、SQLite 数据库、签章和旧镜像；
3. 保持旧容器运行并构建新镜像；
4. 在停服前运行 Docker 端口映射预检，提前发现 `iptables/DOCKER` 链异常；
5. 短暂停止电商客服容器、备份最新数据并切换版本；
6. 等待容器健康检查；失败时自动恢复旧源码、数据和镜像。

默认项目目录是 `/www/wwwroot/ecommerce-training`。如果实际目录不同，把真实绝对路径作为参数：

```bash
sh 电商客服系统-一键更新-日期时间/一键更新.sh /实际项目目录
```

更新不会替换 `docker.env`，不会修改宝塔 Nginx、`training.example.com` 的 SSL、`127.0.0.1:17777` 反向代理或原来的 `666` 系统。更新成功后访问：

```text
https://training.example.com
```

每次更新备份保存在 `/www/backup/ecommerce-training/update-日期时间`。确认新版本长期正常后，再人工决定是否删除过旧备份和回滚镜像。

## 16. 故障排查

### 777 打不开，但容器健康

```bash
curl -v http://127.0.0.1:17777/api/health
curl -v -H 'Host: YOUR_SERVER_IP:777' http://127.0.0.1:777/api/health
/www/server/nginx/sbin/nginx -t
ss -lntp | grep -E ':(777|17777)\b'
```

第一条成功、第二条失败：检查宝塔 `777` 站点和反向代理。两条都成功、外部失败：检查阿里云安全组与宝塔防火墙。

### 登录后又返回登录页

HTTP 阶段应为：

```env
APP_URL="http://YOUR_SERVER_IP:777"
NEXT_PUBLIC_APP_URL="http://YOUR_SERVER_IP:777"
SESSION_COOKIE_SECURE="false"
```

HTTPS 阶段应为：

```env
APP_URL="https://training.example.com"
NEXT_PUBLIC_APP_URL="https://training.example.com"
SESSION_COOKIE_SECURE="true"
```

三项必须配套，修改后执行 `docker compose --env-file docker.env up -d --force-recreate`。

### 502 Bad Gateway

检查：

```bash
docker compose --env-file /www/wwwroot/ecommerce-training/docker.env \
  -f /www/wwwroot/ecommerce-training/docker-compose.yml ps
curl -v http://127.0.0.1:17777/api/health
```

如果内部健康检查失败，查看容器日志；如果内部成功，检查 Nginx 代理目标是否误填为 `777`、`3000` 或 `18080`。正确目标只能是 `http://127.0.0.1:17777`。

### 域名证书申请失败

确认 DNS 已指向 `YOUR_SERVER_IP`、`80/443` 已放行、域名没有错误 CDN/代理记录，并暂时关闭会干扰 ACME 验证的重定向或访问限制。不要修改现有 `666` 站点排查电商客服证书。

### AI 无法使用

确认 `AI_CONFIG_ENCRYPTION_KEY` 使用本地原值，而不是新生成值，然后在管理员后台检查启用的 AI 服务商。
