# AI 与评分机制

本文统一说明模型配置、客户智能体、知识检索、评分报告和本地回退，替代原有分散的提示词、评价体系和报告模板文档。

## 1. AI 调用范围

系统有三类模型调用：

1. 客户智能体：生成开场和后续客户回复；
2. 评分智能体：根据完整对话生成结构化报告；
3. 任务辅助：根据师父输入补全场景、画像、订单和目标。

认证、权限、报名、会话状态、证书和数据库写入不交给模型决定。

## 2. 服务商配置

运行时优先读取数据库中最近更新且启用的 `AiProvider`：

- `baseUrl`：OpenAI 兼容服务地址；
- `model`：模型名称；
- `apiKeyEncrypted`：加密后的 API Key；
- `isActive`：是否启用。

API Key 新格式为 `v2`，使用 AES-256-GCM。密钥派生优先级：

1. `AI_CONFIG_ENCRYPTION_KEY`；
2. 为兼容旧环境才回退到 `SESSION_SECRET`；
3. 开发环境默认值仅供本地使用。

旧 `v1` 密文仍可用 `SESSION_SECRET` 解密。生产环境必须分别设置两条独立随机密钥。

数据库没有可用配置时，可通过 `AI_MODE`、`OPENAI_BASE_URL`、`OPENAI_API_KEY` 和 `OPENAI_MODEL` 使用环境变量配置。

## 3. 请求行为

- 接口：`POST {baseUrl}/chat/completions`；
- 单次请求超时：45 秒；
- 最多尝试 2 次；
- 408、429、5xx 和网络错误允许重试；
- 客户与评分失败时进入本地回退；
- 任务辅助失败时直接返回错误，不生成伪造结果。

模型返回的 JSON 会尝试从纯 JSON、Markdown 代码块或包含 JSON 的文本中提取。

## 4. 客户智能体

### 输入

- 任务场景与难度；
- 产品说明、规则、标准话术和禁用话术；
- 客户画像与订单信息；
- FAQ 检索结果；
- 完整历史对话；
- 当前情绪、信任、解决进度、客户合作倾向、有效服务轮次和是否已接受方案。

### 输出

```json
{
  "reply": "客户回复",
  "state": {
    "emotion": 78,
    "trust": 24,
    "resolution": 8,
    "disposition": "rational",
    "goodServiceTurns": 0,
    "accepted": false
  }
}
```

数值状态会限制在 0 到 100。客户不能替徒弟给出标准答案，也不能虚构系统已经退款、赔付或完成后台操作。模型只负责生成自然语言，状态变化和是否接受方案由本地确定性规则决定，避免模型在优质回复后反向提高情绪或降低解决进度。

### 客户合作倾向

每次新建会话时随机生成一次合作倾向，并保存在会话状态中；同一会话不会中途变人格。

| 难度 | 普通理性 | 谨慎确认 | 高要求 |
|---|---:|---:|---:|
| 简单 | 90% | 8% | 2% |
| 中等 | 82% | 14% | 4% |
| 困难 | 72% | 20% | 8% |

难度代表争议复杂度和初始情绪，不等于客户必然无理取闹。普通理性客户获得完整方案后立即接受；谨慎客户可以确认一个仍未说明的关键点；高要求客户最多多确认一轮，不能无限追加条件。

### 售后常识边界

- 七天无理由退货且商品完好时，退回运费原则上由消费者承担，另有约定除外；
- 商品确实不符合质量要求时，退换修所需的必要运输费用由经营者承担；
- 打开包装进行合理查验、试穿或调试，只要不影响商品原有品质、功能和外观，不应当然认定为不能退货；
- 额外惩罚性赔偿需要欺诈等事实和法定依据，不能因为客户提出就默认成立；
- 客户可以依法投诉，但不得利用投诉举报牟取不正当利益；
- 客服完整说明退款、运费、赔偿依据、审核条件和时效后，客户应当接受合理结论。

### 对话收敛

规则引擎会检查学生是否同时给出处理方案、审核边界、反馈时效，并回答客户已经提出的运费和赔偿问题。满足条件后，系统直接生成接受方案的话术，不再请求模型继续抬杠；已经接受的客户后续只会确认等待处理，不会重新制造争议。

### 本地回退

模型不可用时，`lib/customer.ts` 根据关键词调整客户状态并返回确定性回复。它保证训练可继续，但不具备模型的上下文理解能力。

辱骂、威胁、敌对驱赶、机械复读和低信息短句不交给模型自由判断，而由确定性岗位质检规则接管该轮客户反应。这样可以避免模型因为一句风险话术中同时出现“理解、退款、24小时”等表面关键词而错误提高信任或解决进度。

## 5. 实时语言质检

`lib/service-language-lexicon.ts` 保存客服岗位专用风险词库，`lib/service-quality.ts` 负责文本归一化、风险匹配和重复度分析。

检测前会进行：

- Unicode NFKC 归一化和大小写统一；
- 移除空格、标点和常见分隔符；
- 压缩故意重复的字符；
- 识别部分拼音、首字母和符号穿插变形；
- 使用字符二元组 Dice 相似度识别高度相似回复。

词库只覆盖客服岗位相关的辱骂、人身攻击、威胁、性别侮辱、敌对驱赶和指责推诿，不直接导入政治、医疗、商品名称等“大而全”敏感词，以免造成业务误报。

触发后：

1. 当前回复仍会保存，作为可追溯的评分证据；
2. 页面立即弹出职业红线或低质量回复警告；
3. 客户情绪上升、信任和解决进度下降；
4. 对应消息标红并记入实时质检；
5. 最终报告生成风险条目、扣分并执行总分封顶。

## 6. FAQ 检索

当前实现不是向量 RAG：

1. 读取目标产品知识和通用知识；
2. 最多处理最近 30 份文档；
3. 从查询中提取英文/数字词元和相邻中文二元组；
4. 按标题、来源和正文命中计分；
5. 截取最多 80 个知识片段并返回得分最高项。

知识只用于模型参考，不直接显示为徒弟标准答案。知识量明显增长后，应改为数据库全文检索或向量检索，并增加租户/产品隔离测试。

## 7. 六维评价

| 维度 | 标准上限 | 评价重点 |
|---|---:|---|
| 客户问题洞察 | 15 | 争议识别、订单、证据、签收时间、客户期望和有效追问 |
| 情绪安抚 | 15 | 前两轮共情、道歉、主动负责，避免对抗和虚假安抚 |
| 规则运用 | 15 | 售后条件、证据用途、条件化承诺和平台边界 |
| 服务策略 | 20 | 具体方案、客户动作、时效、跟进责任和接受确认 |
| 风险控制 | 20 | 辱骂、威胁、推责、平台外交易、删评撤诉和越权承诺 |
| 表达质量 | 15 | 信息密度、逐轮差异、结构、针对性和真实推进 |

报告总分范围为 0 到 100，普通报告 70 分通过，正式考核 80 分发证。等级由总分映射，重大风险还会触发封顶。

### 逐轮实时评分

每条学生回复都必须生成一条独立评分记录，记录包括：回合编号、对应客户消息、当前阶段、阶段权重、六维表现、本轮原始分、本轮扣分、封顶分、实际得分、优点、问题和改进建议。

系统根据对话进度使用不同的 100 分阶段量表：

| 阶段 | 主要权重 | 回合系数 |
|---|---|---:|
| 接待安抚 | 洞察 25%、情绪 30%、风险 15% | 1.15 |
| 事实核实 | 洞察 30%、规则 20%、风险 15% | 1.00 |
| 方案推进 | 规则 20%、方案 30%、风险 15% | 1.25 |
| 闭环确认 | 方案 30%、风险 20%、表达 15% | 1.15 |

首轮不会因为尚未给出最终方案而被不合理扣分；后续回合也不能只靠共情套话获得高分。每个新增回合都会进入加权分母，因此追加低质量回复会真实拉低综合成绩。

实时成绩是“截至当前回合的阶段综合分”，不是锁定的最终成绩。发送新回复后，服务端会基于全部聊天记录重新计算，并把当前综合分、六维分、累计扣分和当前封顶值返回页面。

### 最终加权公式

每个六维分项都由两部分组成：

```text
六维分项 = 本维度逐轮阶段加权表现 × 70% + 本维度全程能力覆盖 × 30%
原始分 = 六个维度分相加
最终分 = 原始分 - 复读/低信息全局扣分，再执行风险、最低轮次和方案完整性封顶
```

“逐轮表现”保证每一次对话都有影响；“全程能力覆盖”避免学生只在某一轮堆叠所有关键词。两者结合后，最终报告同时保存逐轮轨迹和公式参数，便于师父复核。

公平性约束：

- 客户已提供订单号、照片或吊牌信息时，学生应确认并使用信息；重复索要会扣分；
- 每类证据按是否真实出现计算，同一句话重复多次不会重复获得覆盖分；
- 只统计布尔证据和阶段完成度，不按字数直接加分，避免长文本刷分；
- 后发的高分话术不能删除或覆盖前面的弱回复、辱骂和风险记录；
- 所有硬性风险由程序计算，模型只能润色文字解释；
- 一轮、两轮、无方案、机械复读和重大风险都有独立封顶，封顶取最严格值。

## 8. 确定性评分与硬性封顶

`lib/scoring.ts` 是所有实时分和最终分的唯一数值基准，而不只是模型故障时的回退。它逐轮分析对话证据：

- 同一能力点只按真实证据计分，不会因复制同一句模板而反复加分；
- 完全重复每次额外扣分，高度相似回复也扣分；
- “好的、稍等、知道了”等低信息短句按无效推进扣分；
- 只有一轮或两轮就提交会分别触发 45 分、65 分封顶；
- 没有任何实质处理方案时最高 69 分，不能通过；
- 多次复读或回复区分度过低时最高 50～60 分；
- 敌对推责或平台外处理最高 60～65 分；
- 人身攻击、脏话、威胁和性别侮辱最高 25～40 分。

单维分数始终限制在维度上限内。`rawScore` 为六维加权合计，`totalScore` 为执行重复扣分和风险封顶后的最终成绩。`turnScores` 保存逐轮轨迹，`scoringMethod` 保存本次实际使用的权重、扣分和封顶口径。

## 9. 评分智能体输出

评分报告至少包含：

```json
{
  "totalScore": 82,
  "rawScore": 82,
  "level": "良好",
  "passStatus": "通过",
  "summary": "总体诊断",
  "dimensions": [
    {
      "name": "客户问题洞察",
      "score": 12,
      "maxScore": 15,
      "reason": "评分理由",
      "evidence": ["对话证据"],
      "improvement": "改进建议"
    }
  ],
  "riskItems": [],
  "strengths": [],
  "weaknesses": [],
  "recommendedScript": "建议话术",
  "nextPractice": "下一步训练"
}
```

数据库同时保存总分字段和完整 JSON。成长画像从 `dimensions` 聚合；前端报告读取总结、风险、优势、问题和建议话术。

评分模型只能润色总结、证据解释和改进建议。服务端会强制保留程序计算的：

- 六维名称、分数和上限；
- `rawScore`、`totalScore`、等级和通过状态；
- 语言风险条目和封顶结果；
- 强弱项标签的数值依据。

即使模型返回更高分或删除风险项也不会生效。

## 10. 当前校验边界

当前已强制六维上限、数值基准、等级、通过状态、语言风险和封顶结果。仍需注意：词库永远无法覆盖所有新造词、谐音、方言和强语境攻击；规则命中也可能存在边界案例。因此重大考核报告仍保留师父审核流程，后续可在独立测试集上评估召回率、误报率和不同群体语言偏差。

## 11. 师父复核

师父可调整总分和文字反馈。服务端重新计算等级和通过状态，但当前不会重新计算六维合计或风险封顶。重复复核时 `rawScore` 的历史基线也可能被上一轮复核覆盖。

如果需要审计级评价，应增加不可变的 AI 原始报告、复核版本表、修改原因和操作时间线。

## 12. 设计依据与词库维护

- 中文攻击性语言分类和检测难点参考 [COLD：中文攻击性语言检测基准（EMNLP 2022）](https://aclanthology.org/2022.emnlp-main.796/)；
- 词库组织、业务场景裁剪和 Trie/正则匹配思路参考采用 MIT 许可的 [Sensitive-lexicon](https://github.com/konsheng/Sensitive-lexicon)；
- 客服质检的实时预警与报告定位参考 [淘宝开放平台客服质检类目规则](https://developer.alibaba.com/docs/doc.htm?articleId=121760&docType=1&treeId=253)；
- B2C 顾客满意与投诉处理的总体原则参考现行国家标准 [GB/T 19018-2017](https://std.samr.gov.cn/gb/search/gbDetailedCNF?id=71F772D81F3DD3A7E05397BE0A0AB82A)。
- 七天无理由退货、质量问题退货和运费责任依据 [《中华人民共和国消费者权益保护法》第二十四、二十五条](https://www.samr.gov.cn/zfjcj/tzgg/art/2023/art_615af9ed6bcd4974bf853dd2e02bc663.html)；
- 合理查验、诚信退货、理性投诉和防止利用投诉牟利依据 [《中华人民共和国消费者权益保护法实施条例》](https://app.www.gov.cn/govdata/gov/202403/19/513111/article.html)；
- 网络退货程序、退款方式和七天无理由退货运费依据 [《网络购买商品七日无理由退货暂行办法》](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_26ca8fe29e184edd899fa0a7a060d935.html)。

“全网违禁词”不存在稳定、权威且零误报的单一清单。项目采用可解释的岗位词库加文本变形规则，并要求新增词条必须附真实客服用例、严重级别、误报反例和建议替代话术。

## 13. 修改检查清单

- 客户输出字段变化：同步 `lib/types.ts`、AI 客户端、会话状态和训练 UI；
- 报告字段变化：同步 AI 校验、数据库 JSON 兼容、报告页面和成长聚合；
- 阈值变化：同步评分、报告通过、正式考核、证书和页面颜色；
- 风险规则变化：同时修改本地评分、AI 提示、服务端归一化和测试案例；
- 模型配置变化：验证旧密文解密、密钥轮换和环境变量回退。
